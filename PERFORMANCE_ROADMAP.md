# Performance Roadmap

## Статус реализации

CPU-оптимизация реализована:

- модель по умолчанию — `base.en`;
- VAD silence — 350 мс;
- LLM debounce — 400 мс;
- partial STT включён с интервалом 800 мс и минимумом аудио 700 мс;
- partial/final используют стабильный ID и обновляют одну карточку;
- очередь partial хранит только последний snapshot, final имеет приоритет;
- только final-текст отправляется в OpenRouter;
- добавлены latency и RTF-метрики без текста.

`WHISPER_CPU_THREADS=4` не изменён. GPU-оптимизация не выполнялась, поскольку
NVIDIA GPU отсутствует.

## Цель

Сократить задержку появления транскрипции с текущих 3–5 секунд до 1–2 секунд,
не ухудшая заметно качество распознавания технической речи.

## Текущие источники задержки

- `VAD_SILENCE_MS=600`: ожидание окончания речи — около 0,6 секунды.
- Whisper `small.en` на CPU: обычно 1–3 секунды.
- `LLM_DEBOUNCE_DELAY_S=1.2`: карточка создаётся только после дополнительного
  ожидания 1,2 секунды.

Сетевой запрос OpenRouter влияет на появление AI-ответа, но не должен задерживать
показ уже распознанного текста.

## Этап 1 — быстрые настройки

Проверить следующий профиль:

```env
WHISPER_MODEL=base.en
VAD_SILENCE_MS=350
LLM_DEBOUNCE_DELAY_S=0.4
WHISPER_BEAM_SIZE=1
WHISPER_COMPUTE_TYPE=auto
```

- Если `base.en` недостаточно быстр, проверить `tiny.en`.
- Число CPU-потоков зафиксировано на `WHISPER_CPU_THREADS=4`.
- Не опускать `VAD_SILENCE_MS` значительно ниже 250–300 мс, чтобы не разрезать
  естественные паузы внутри вопроса.

## Этап 2 — разделить транскрипцию и LLM debounce

Изменить UX и pipeline:

1. Показывать результат Whisper сразу после завершения STT.
2. Продолжать накапливать фрагменты во внутреннем буфере.
3. Использовать debounce только перед объединением вопроса и вызовом OpenRouter.
4. Обновлять одну предварительную карточку объединённым текстом, а не создавать
   зависшие карточки для каждого фрагмента.
5. AI-ответ стримить в эту же карточку.

Это уберёт из видимой задержки весь `LLM_DEBOUNCE_DELAY_S`.

## Этап 3 — ускорение на GPU (не применяется)

При наличии совместимой NVIDIA GPU проверить:

```env
WHISPER_DEVICE=cuda
WHISPER_COMPUTE_TYPE=float16
```

Перед включением убедиться, что установлен совместимый GPU build CTranslate2 и
нужные CUDA-библиотеки. Сравнить время STT, расход VRAM и стабильность с CPU
`int8`.

## Этап 4 — частичная транскрипция (реализовано)

- распознавать накопленное аудио каждые 0,5–1 секунду во время речи;
- показывать нестабильный хвост отдельно от подтверждённого текста;
- дедуплицировать перекрывающиеся результаты;
- финализировать текст после VAD end;
- отправлять в LLM только финализированный объединённый вопрос.

Нагрузка ограничена одним inference и latest-only partial mailbox, поэтому
устаревшие snapshots не образуют очередь.

## Измерения и критерии готовности

Добавить метрики:

- `speech_end -> STT_result`;
- `STT_result -> transcript_visible`;
- `speech_end -> first_LLM_token`;
- real-time factor Whisper;
- модель, устройство и compute type.

Целевые значения:

- транскрипт виден не позднее 1,5 секунды после окончания короткого вопроса;
- первый AI-токен — не позднее 2,5 секунды при нормальной сети;
- вопросы не дробятся заметно чаще;
- технические термины распознаются приемлемо по сравнению с `small.en`.

## Дальнейшая проверка

1. Замерить latency на реальном loopback-аудио.
2. Проверить короткие и длинные технические вопросы.
3. При высокой CPU-нагрузке увеличить partial interval, не меняя число потоков.
