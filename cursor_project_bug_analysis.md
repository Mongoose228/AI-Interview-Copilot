## Критичные

**1. Речь кандидата уходит в LLM при облачном распознавании речи.** Транскрипты Deepgram, Groq и Soniox собираются без поля `speaker`, и оно по умолчанию становится `"interviewer"`. Микрофонные фразы при двухканальной записи идут через `transcribe()`, поэтому фильтр `speaker == "candidate"` их не отсекает. В итоге ваши собственные ответы попадают в LLM как вопросы интервьюера. С Whisper такого нет: там `speaker` передаётся.

```129:141:src/interview_copilot/stt/deepgram.py
            return Transcript(
                phrase_id=phrase.id,
                text_en=text,
                language=self._language,
                confidence=conf,
                stt_duration_s=ended - started,
                stt_started_at=started,
                stt_ended_at=ended,
                is_final=phrase.is_final,
                revision=phrase.revision,
                speech_started_at=phrase.captured_at,
                speech_ended_at=phrase.vad_end_at,
                audio_duration_s=phrase.duration_s,
            )
```

**2. Поток Deepgram умирает навсегда.** Нет ни переподключения, ни сообщений `KeepAlive`. Если WebSocket закрылся (сбой сети или больше ~10 с без аудио), `feed_audio` молча выбрасывает весь звук до перезапуска приложения. Тишину в потоке легко получить: пока говорит кандидат, звук в Deepgram не отправляется (`if self._streaming_stt and not mic_speaking`). Длинный ответ кандидата может убить распознавание.

**3. Предварительное распознавание (tiny Whisper) выполняется прямо в потоке захвата звука.** Это `maybe_provisional` в `pipeline.py`, строки 345–367, и так работает конфигурация по умолчанию: whisper + dual-path. Пока tiny-модель заново распознаёт всю фразу (раз в 800 мс), поток не читает аудио. Отсюда пропуски звука и переполнение очереди микрофона, где теряется 30 чанков за раз. Похоже, это и есть источник предупреждений `data discontinuity`, которые специально заглушены в `soundcard_wasapi.py:14`.

**4. Нормализация громкости считается отдельно для каждого 20-мс чанка** (`dsp.py`, `normalize_peak`, усиление до ×8). Громкость скачет 50 раз в секунду, тихий фон усиливается, а распознаванию и VAD приходит искажённый сигнал. Заодно выяснилось, что `light_denoise` на 20-мс чанке не выполняется вообще: 320 сэмплов меньше порога в 1600. Галочка «Light denoise» в настройках ни на что не влияет.

**5. Ctrl+Shift+H скрывает окно без возможности вернуть.** `QShortcut` срабатывает только когда окно активно, а у скрытого окна с флагом `Qt.Tool` нет и значка на панели задач. Вернуть окно можно только убив процесс. Заодно: Esc мгновенно закрывает приложение без подтверждения, легко нажать случайно посреди интервью.

## Средние

- **Failover между движками распознавания никогда не срабатывает.** `FailoverSttEngine` переключается на запасной движок только при исключении. Но Deepgram, Groq и Soniox ловят все ошибки сами и возвращают пустой текст. При падении API вы просто получаете тишину.
- **Ключи из Settings не применяются до перезапуска.** Код с комментарием «Hot-apply keys» пишет их в `config`, но `OpenRouterSuggester` и STT-движки уже созданы со старыми ключами. В подсказке про перезапуск упомянут только backend. Пользователь вводит ключ OpenRouter, а видит прежнее «Suggestions disabled».
- **Soniox можно выбрать в настройках, но ключ не задать.** В диалоге нет поля для него, а в `settings_store._KEYS` нет `SONIOX_API_KEY`.
- **Постоянные ошибки в статусе стираются.** `on_audio_status` в `app.py` вызывает `clear_persistent_error()` при каждом подключении аудио. Сообщение «OpenRouter API key not set» исчезает почти сразу после старта, а также после смены устройства или паузы.
- **Фразы с микрофона транскрибируются впустую.** Они идут в общую очередь распознавания, хотя результат потом выбрасывается. Это лишняя нагрузка на CPU или платные запросы, и из-за неё задерживаются фразы интервьюера.
- **Двойное распознавание при `STT_CLOUD_ENDPOINTING=False` с Deepgram.** Финальные фразы приходят и из потока, и из HTTP-запроса по фразам от VAD. Текст вопроса дублируется, а платите вы дважды.
- **Мусорные карточки при Deepgram + dual-path.** Предварительные результаты tiny Whisper и промежуточные результаты Deepgram используют разные id фраз. Текст карточки мерцает, а записи для id от VAD никогда не удаляются. Если Deepgram ничего не вернул, карточка «Listening…» остаётся навсегда.
- **Подсказка может не прийти совсем.** `flush_pending` ждёт `while vad.is_speaking`. При постоянном фоне (музыка, шум) VAD после принудительной нарезки по 12 с остаётся в состоянии «говорит», и подсказка не отправляется.
- **Остановка аудио из другого потока.** `pause_capture` и `change_device` вызывают `audio.stop()` из GUI-потока, пока поток захвата сидит внутри `recorder.record()`. Для COM/WASAPI это небезопасно и может привести к падению на уровне нативного кода.
- **Звук портится при `DSP_ENABLED=False` с Deepgram.** Стерео-чанк превращается в одномерный массив через `reshape(-1)` и уходит в Deepgram с заявленным `channels=1`.
- **Падение при старте из-за запасного Whisper.** `_build_fallback` создаёт Whisper без `skip_if_unavailable`. Если модель не скачалась (офлайн, прокси), не стартует весь пайплайн, даже когда основной движок облачный.

## Мелкие

- В `_process_transcript` используется `asyncio.gather` без `return_exceptions`. Если перевод упадёт, ответ LLM продолжит приходить в карточку, хотя она уже помечена как «failed».
- `sanitize_for_prompt` вырезает `system:` и `you are now`, поэтому портит обычный текст профиля: «Operating system: Linux» превращается в «Operating [FILTERED]Linux».
- Если есть только `example_profile`, в выпадающем списке показан он, хотя активного профиля нет. Выбрать его нельзя, потому что событие смены не срабатывает.
- `stop()` вызывает `vad.flush()` параллельно с работающим потоком захвата, и эта фраза всё равно никогда не обрабатывается: мёртвый код с гонкой.
- `_tokens_seen` растёт без ограничения. Очередь микрофона не очищается при перезапуске захвата.
- Groq создаёт новый клиент OpenAI, а Deepgram новый `httpx.Client` на каждую фразу: лишние 100–300 мс на установку соединения.
- В тайминге STT `ended_at=... or transcript.stt_duration_s` подставляет длительность вместо временной метки.
- `cmd_run` в CLI не вызывает `apply_prefs_to_config`, поэтому ключи, сохранённые через GUI, в CLI не работают.
- Если ключ хранилища недоступен (`keyring`), секреты сохраняются открытым текстом в `%APPDATA%\interview_copilot\user_prefs.json`.
